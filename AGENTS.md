# Rules for coding agents

This file restates the repo conventions for coding agents. The human-facing
version, with setup and release details, is [CONTRIBUTING.md](CONTRIBUTING.md).

## Non-negotiable

- **Never push to `main`.** Every change reaches `main` through a pull request.
  Direct pushes are blocked by a branch ruleset; do not try to work around it.
- **Open PRs with a typed template and fill in every section:**

  ```sh
  gh pr create --template <type>.md   # feat.md | fix.md | docs.md | chore.md | refactor.md | ci.md
  ```

  Leaving a section empty or deleting it is not acceptable. `fix.md` also
  needs Bug, Root cause and Reproduction.
- **PR titles are Conventional Commits** (`type(scope)?: subject`, 100 chars
  max). The title becomes the squash-merge commit message.
- **Commits are a single line**: `type(scope)?: subject`, at most 100
  characters. After that line, only a blank line and `Co-authored-by: Name <email>`
  trailers are allowed. No body text; details go in the PR description.
  Allowed types: `feat`, `fix`, `docs`, `chore`, `refactor`, `ci`, `build`,
  `perf`, `style`, `test`, `revert`. Breaking changes use `!` (`feat!: ...`).
- **Merges are squash or rebase only.** History stays linear.
- **Releases are made by merging the Release Please PR**, which is authored by
  `jwallace145-release-bot[bot]`. Do not create tags or releases by hand.

## Working in this repo

- Every module lives in `modules/<name>/` with `main.tf`, `variables.tf`,
  `outputs.tf`, `versions.tf`, `README.md`, `examples/basic/` and `tests/`.
  The repo root is itself a module (the site stack) with the same layout.
  The one exception is the policy leaves under
  `modules/ci-policies/<family>/<name>/`: they are internal to `ci-policies`
  and have no `examples/basic/`. Adding one also means a catalog entry and a
  CI matrix entry with `example: false`; see `modules/ci-policies/README.md`.
- `README.md` in each module is generated by terraform-docs between the
  `BEGIN_TF_DOCS`/`END_TF_DOCS` markers. Regenerate after any input/output
  change: `terraform-docs modules/<name>` (or `terraform-docs .` for the
  root). CI fails on a diff.
- Tests use `terraform test` with `mock_provider "aws"`. CI has **no AWS
  credentials**; never write a test that needs them.
- Modules never configure providers. Everything targets `us-east-1`.
- Run the same checks CI runs before opening a PR:

  ```sh
  terraform fmt -check -recursive
  for m in . $(find modules -name versions.tf -not -path '*/examples/*' -not -path '*/.terraform/*' -exec dirname {} \; | sort); do (cd "$m" && terraform init -backend=false && terraform validate && tflint --config "$OLDPWD/.tflint.hcl" && terraform test); done
  for m in . $(find modules -name versions.tf -not -path '*/examples/*' -not -path '*/.terraform/*' -exec dirname {} \; | sort); do terraform-docs "$m"; done && git diff --exit-code
  npm ci && npm run test:commitlint
  ```

- Any breaking change to a module's inputs or outputs is `feat!` or `fix!`.
